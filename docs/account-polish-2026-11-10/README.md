# Account and tracking polish — 2026-11-10

- [Layout]: Cart and checkout palette kept. Desktop has an account guide/profile beside the forms; phone uses a compact header and one column. Scrollable body, sticky section navigation, fixed close/logout footer. Inputs 16px/52px; touch targets at least 44px.
- [Authentication]: Dedicated login/register views, password reveal with accessible state, appropriate autocomplete, pending request lock and focused errors. Successful login keeps the dialog open and focuses the account overview. Password values reset when switching views. Logout only closes through the parent after success.
- [Orders]: Separate account history and receipt tracking. Cards show the real server status, order number, Tehran date, quantity, shipping and total. Native details reveal line items. Pending payment and reservation expiry remain explicit. No invented shipment timeline or payment confirmation.
- [Tracking]: Saved device receipts remain distinct from account ownership. Guest key required; account-owned orders may use the number alone. Key stays in the request header. Edits/cancel abort the pending lookup and invalidate late replies; a newer request remains busy until its own response. Errors and returned cards receive focus. Result aligns below sticky navigation.
- [History]: Loading/error/empty states stay distinct. Retry and pagination retain loaded cards. Old account replies cannot populate a new account. Paging deduplicates displayed cards while advancing by consumed response count.
- [Motion]: Shared dialog entrance/exit extracted from checkout without changing checkout behavior. Opacity/transform entrance 250ms, exit 180ms; section/result/card reveals 180–220ms. Existing easing and pending-button feedback reused. Keyboard and reduced-motion paths skip travel. No new dependency.
